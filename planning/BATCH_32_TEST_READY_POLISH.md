# Batch 32 — Test-ready polish

## Goal
Make the hub feel easier to test in a single pass by improving:
- first-click clarity
- navigation + search discoverability
- reading comfort on long pages
- recovery paths when users hit dead ends

## What changed
- Added a global skip link for accessibility.
- Added a thin scroll progress bar so long pages feel more premium and more readable.
- Added search access to the navbar utility + primary CTA cluster.
- Added a homepage jump strip so testers can move through the large homepage faster.
- Added a dedicated search CTA in the hero.
- Improved search with:
  - enter-to-submit
  - quick suggestion chips
  - browse cards when a query is too broad
  - better no-results recovery
- Upgraded the 404 page with search + strong recovery routes.
- Improved content pages with breadcrumbs and a sticky right sidebar.
- Tightened card CTA language so buttons match the content type more naturally.

## Why this batch matters
At this stage, the biggest risk is not a lack of content. It is that the site feels broad enough to overwhelm a first-time tester.

This polish pass reduces friction in the exact places a human tester notices first:
- how quickly they can orient themselves
- how easily they can recover from a wrong click
- whether long pages still feel guided
- whether the site looks intentionally designed, not merely expanded

## Suggested next phase after testing
Use real test notes to decide which of these to strengthen next:
- homepage reduction / simplification
- stronger school-fit conversion blocks
- stronger housing conversion blocks
- direct proof once approved parent quotes exist
- analytics cleanup around tool starts vs page exits
