# Batch 29 — Technical + editorial governance

## Goal
Make the site feel more premium and more trustworthy as it grows by adding a visible governance layer.

## What this batch adds
- optional `governance` front matter support in the content model
- public `/editorial-standards` page
- public `/content-health` page
- generated `src/generated/governanceReport.json`
- page-level governance strip inside the content layout
- validation support for governance fields
- sitemap/footer updates for the new trust pages

## Governance model
We are not reviewing every page at the same speed.

### Tight cadence
Use tighter cadences where drift causes bigger family mistakes:
- visas / official links
- housing / lease / deposits
- Gaia Group path
- costs / budgeting
- Empathy School fit / tours / camps

### Standard cadence
Use normal cadences for:
- core pillars
- area guides
- major move-planning pages

### Long cadence
Use longer cadences for:
- templates
- resource sheets
- story pages
- recap content that is mainly interpretive

## Evidence labels
- `experience-based`
- `reviewed`
- `official-links`

These labels should be visible enough that a family understands how to use the page.

## Why this matters
The site is now large enough that trust cannot live only in tone.
It needs visible systems:
- review cadence
- ownership
- disclosure
- page freshness
- clear labeling when a story is composite
